# هم‌صدا (HamSeda) — بی‌سیم آفلاین اندروید

هم‌صدا یک اپلیکیشن **بومی اندروید** (Kotlin + Jetpack Compose) برای گفتگوی صوتی
**push-to-talk** بین گوشی‌های نزدیک است — **کاملاً آفلاین**: بدون اینترنت،
بدون حساب کاربری، بدون سرور، بدون سرویس ابری.

- **حمل‌ونقل اصلی:** Wi-Fi Direct (Wi-Fi P2P) — اتصال مستقیم گوشی‌به‌گوشی، بدون روتر و بدون اینترنت
- **حمل‌ونقل دوم:** Bluetooth Classic (RFCOMM)
- **امنیت:** نشست احرازهویت‌شده با ECDH موقتی روی منحنی P-256، مشتق کلید
  HKDF-SHA-256، رمزنگاری AES-256-GCM روی همه فریم‌های صوتی و کنترلی، و مقایسه
  کد امنیتی ۶ رقمی (SAS) توسط هر دو کاربر قبل از شروع صدا
- **صدا:** کدک Opus (پورت خالص جاوای Concentus، داخل APK) با فریم‌های ۲۰ میلی‌ثانیه‌ای،
  حدود ۲۰ کیلوبیت بر ثانیه؛ جایگزین PCM برای عیب‌یابی
- **رابط کاربری:** فارسی و راست‌به‌چپ در همه صفحه‌ها، پوسته روشن (پیش‌فرض) و تیره

> **صداقت فنی:** این پروژه ادعای «غیرقابل نفوذ»، «برد نامحدود» یا «کار روی همه گوشی‌ها»
> ندارد. محدودیت‌های واقعی پلتفرم و سخت‌افزار در بخش «محدودیت‌ها» و فایل
> `SECURITY.md` آمده است. هیچ بخشی از ارتباط از سرور یا سرویس آنلاین استفاده نمی‌کند.

## ویژگی‌ها

| قابلیت | توضیح |
|---|---|
| Push-to-talk نیمه‌دوطرفه | نگه‌داشتن دکمه بزرگ برای صحبت، رها کردن برای قطع فوری؛ فقط یک نفر هم‌زمان |
| کنترل نوبت (floor control) | درخواست/اعطا/رد با lease زمانی؛ گیر کردن کانال با کرش هم‌صحبت غیرممکن |
| نشست امن | ECDH موقتی + HKDF-SHA-256 + AES-256-GCM؛ مقایسه SAS ۶ رقمی توسط کاربر |
| حالت‌های اتصال | Wi-Fi Direct (پیش‌فرض)، بلوتوث، یا «خودکار (توصیه‌شده)» — جابه‌جایی هیچ‌وقت حین صحبت مخفیانه انجام نمی‌شود |
| صدای کم‌تأخیر | AudioRecord/AudioTrack با پیکربندی `VOICE_COMMUNICATION`، جیتربافر تطبیقی، مدیریت AudioFocus و تغییر مسیر خروجی |
| افکت‌های صوتی | AcousticEchoCanceler / NoiseSuppressor / AutomaticGainControl فقط در صورت پشتیبانی سخت‌افزار |
| سرویس پیش‌زمینه | با نوع `microphone`؛ اعلان دائمی با دکمه توقف؛ میکروفون فقط با اقدام کاربر باز می‌شود |
| حریم خصوصی | بدون ذخیره صدا، بدون تاریخچه، بدون مخاطب؛ کلیدها موقتی و با پایان نشست از حافظه پاک می‌شوند |

## نصب و اجرا

1. از صفحه [Actions ریپازیتوری](#دانلود-apk-از-github-actions)، آرتیفکت
   `HamSeda-debug-apk` را دانلود و روی گوشی نصب کنید (نصب از منبع ناشناس را
   برای همین فایل مجاز کنید).
2. روی **دو گوشی** نصب کنید.
3. برای اولین آزمایش، روی هر دو گوشی **یک حالت اتصال یکسان** انتخاب کنید.
   برای جلوگیری از انتخاب مسیر متفاوت، ابتدا حالت «وای‌فای دایرکت» یا
   «بلوتوث» را به‌صورت دستی انتخاب کنید؛ حالت خودکار ممکن است روی دو گوشی
   مسیرهای متفاوتی برگزیند.
4. روی گوشی **منتظر (B)**، «یافتن هم‌صحبت» را باز کنید و «شروع انتظار» را بزنید.
   در حالت بلوتوث، درخواست سیستمیِ قابل‌مشاهده‌شدن را هم تأیید کنید و این
   گوشی را در حالت انتظار نگه دارید.
5. روی گوشی **آغازکننده (A)**، همان حالت اتصال را انتخاب کنید، «جستجو» را بزنید
   و پس از ظاهرشدن گوشی B، روی «اتصال امن» بزنید. فقط یک گوشی باید اتصال را
   آغاز کند؛ گوشی دیگر باید در حالت انتظار بماند.
6. روی هر دو گوشی **کد امنیتی ۶ رقمی** نمایش داده می‌شود. آن‌ها را با هم مقایسه
   کنید و فقط در صورت یکسان‌بودن «کدها یکی‌اند» را بزنید.
7. دکمه بزرگ را **نگه دارید** و صحبت کنید؛ رها کنید تا قطع شود.

## تضمین آفلاین بودن

همه قابلیت‌های زمان اجرا (کشف، جفت‌سازی، صدا، تنظیمات) بدون اینترنت کار می‌کنند:

- هیچ سوکتی به IP عمومی باز نمی‌شود؛ هیچ DNS، HTTP، WebView، تحلیل رفتار،
  تبلیغات یا گزارش خرابی ابری در اپ وجود ندارد.
- مجوز `INTERNET` در مانیفست **فقط** به این دلیل اعلام شده که اندروید برای باز
  کردن سوکت TCP محلی (سوکت‌های Wi-Fi Direct گوشی‌به‌گوشی) به آن نیاز دارد؛
  هیچ ترافیکی به اینترنت ارسال نمی‌شود.
- وابستگی‌های زمان اجرا داخل APK باندل‌اند. اینترنتِ زمان **بیلد** (دانلود
  وابستگی‌های Gradle در GitHub Actions) با عملکرد آفلاینِ زمان **اجرا** فرق دارد.

**روش تأیید آفلاین (قابل تکرار):**
1. APK را نصب کنید.
2. دیتای موبایل را خاموش کنید؛ حالت پرواز را روشن کنید؛ سپس در صورت اجازه
   دستگاه، وای‌فای و بلوتوث را دستی دوباره روشن کنید.
   (نکته: در بعضی گوشی‌ها حالت پرواز وای‌فای را کامل می‌بندد — در این صورت
   به‌جای حالت پرواز فقط «دیتای موبایل» و «وای‌فای متصل به اینترنت» را خاموش کنید.)
3. روی دو گوشی بدون هیچ اتصال اینترنتی، کشف و گفتگو را تست کنید.

## مجوزها

| مجوز | چرا لازم است |
|---|---|
| `INTERNET` | فقط برای سوکت‌های TCP محلی Wi-Fi Direct (ترافیک اینترنت: هرگز) |
| `ACCESS_LOCAL_NETWORK` (فقط اندروید ۱۷+) | اندروید ۱۷ دسترسی به شبکه محلی را پیش‌فرض می‌بندد؛ سوکت Wi-Fi Direct بدون این مجوز بی‌صدا بلاک می‌شود. قبل از اتصال، با توضیح درخواست می‌شود |
| `ACCESS_WIFI_STATE` / `CHANGE_WIFI_STATE` | عملیات Wi-Fi Direct |
| `NEARBY_WIFI_DEVICES` (با پرچم `neverForLocation`، اندروید ۱۳+) | کشف Wi-Fi Direct بدون استفاده از موقعیت |
| `ACCESS_FINE_LOCATION` (فقط تا اندروید ۱۲) | نیاز پلتفرم برای کشف Wi-Fi Direct در اندروید ۱۰–۱۲ |
| `ACCESS_COARSE_LOCATION` (فقط تا اندروید ۹) | نیاز پلتفرم برای کشف Wi-Fi Direct در اندروید ۸–۹ |
| `BLUETOOTH_SCAN` / `BLUETOOTH_CONNECT` / `BLUETOOTH_ADVERTISE` (اندروید ۱۲+) | کشف و اتصال بلوتوث |
| `BLUETOOTH` / `BLUETOOTH_ADMIN` (فقط تا اندروید ۱۱) | بلوتوث در نسخه‌های قدیمی |
| `RECORD_AUDIO` | فقط هنگام شروع نشست صوتی، با توضیح؛ ضبط فقط حین نگه‌داشتن دکمه |
| `MODIFY_AUDIO_SETTINGS` | حالت `MODE_IN_COMMUNICATION` و بلندگو |
| `FOREGROUND_SERVICE` + `FOREGROUND_SERVICE_MICROPHONE` | سرویس صوتی پیش‌زمینه |
| `POST_NOTIFICATIONS` (اندروید ۱۳+) | اعلان دائمی نشست |
| `VIBRATE` | بازخورد لمسی ارسال |

هیچ مجوزی برای مخاطبین، پیامک، لاگ تماس، موقعیت دقیق، دوربین یا حافظه گرفته نمی‌شود.

## جفت‌سازی و کد امنیتی

1. هر دو گوشی یک جفت‌کلید ECDH **موقتی** روی منحنی P-256 می‌سازند و کلید عمومی را مبادله می‌کنند.
2. کلید مشترک → HKDF-SHA-256 → سه کلید جدا (صدا / کنترل / شناسه نشست) + بذر کد امنیتی.
3. هر دو طرف هش transcript را با کلید کنترل امضا و مبادله می‌کنند؛ عدم تطابق = قطع فوری.
4. **کد ۶ رقمی** روی هر دو گوشی نمایش داده می‌شود. آن را با هم مقایسه کنید
   (بلند بخوانید یا کنار هم بگذارید). این کد *مصالحه‌ناپذیر* است: مهاجم
   میانیِ فعال نمی‌تواند کاری کند که هر دو گوشی یک کد یکسانِ اشتباه نشان دهند،
   مگر اینکه تبادل کلید را هم بشکند — که آن هم در مرحله ۳ لو می‌رود.
5. فقط وقتی **هر دو** «کدها یکی‌اند» را زدند، صدا فعال می‌شود.

> توجه: نام بلوتوث/وای‌فای دستگاه‌ها فقط برای نمایش است و هرگز به‌عنوان هویت
> پذیرفته نمی‌شود.

## محدودیت‌های دستگاه

- **Wi-Fi Direct** به سخت‌افزار و درایور گوشی بستگی دارد؛ بعضی گوشی‌ها (مخصوصاً
  قدیمی‌ترها) در مذاکره group-owner ناپایدارند. اگر اتصال برقرار نشد، حالت
  بلوتوث را امتحان کنید.
- **بلوتوث:** فقط یک‌به‌یک. پهنای باند واقعی RFCOMM بین گوشی‌ها متفاوت است؛
  Opus پیش‌فرض (~۲۰kbps) با حاشیه امن جا می‌شود.
- **BLE** عمداً برای صدا استفاده نشده (توان عملیاتی کافی برای صدای زنده ندارد).
- کیفیت/تأخیر صدا روی سخت‌افزار واقعی باید اندازه‌گیری شود؛ هیچ ادعای عددی
  بدون تست روی دستگاه مطرح نشده است (روش تست: `docs/TEST_PLAN.md`).
- اندروید ۱۲+ برای کشف بلوتوث/وای‌فای مجوزهای زمان‌اجرا می‌خواهد؛ اگر رد شوند،
  اپ مسیر بازیابی را نشان می‌دهد و اصرار نمی‌کند.
- در پس‌زمینه، نشست فقط از طریق سرویس پیش‌زمینه با اعلان دائمی ادامه می‌یابد؛
  با توقف کاربر، میکروفون و سوکت‌ها فوراً آزاد می‌شوند.

## تست

تست‌های واحد JVM با `./gradlew :app:testDebugUnitTest` اجرا می‌شوند و در CI
اجباری‌اند:

- فریمینگ/پارس فریم، اعتبارسنجی حداکثر اندازه، رد فریم‌های خراب
- ECDH دوطرفه، HKDF، رفت‌وبرگشت AES-GCM، رد دست‌کاری/کلید اشتباه/AAD اشتباه، یکتایی nonce
- تطابق SAS دو طرف، حساسیت transcript
- پنجره ضد-replay (تکراری، قدیمی، نامرتب در پنجره)
- کنترل نوبت: اعطا/آزادسازی/رد، timeout lease، سقف ارسال
- جیتربافر: priming، ترتیب، گم‌شدن فریم، حذف کهنه‌ها، سقف حافظه
- کدک: رفت‌وبرگشت PCM (دقیق) و Opus (حفظ انرژی و همبستگی)
- FramedSocket: تحدید فریم‌ها، EOF تمیز، رد طول‌های مخرب
- نشست کامل دوطرفه روی ترانسپورت loopback: handshake → SAS → ورود به نشست → فریم صوتی
- **تشخیص MITM:** دست‌کاری nonce در KEY_EXCHANGE حین انتقال → خطای `AUTH_MISMATCH`
- قطع ناگهانی ترانسپورت حین مکالمه → پایان تمیز نشست

تست‌های instrumented کامپایل می‌شوند (`assembleAndroidTest`)؛ اجرای کامل روی
دستگاه/امیولاتور و سناریوهای دوگوشی در `docs/TEST_PLAN.md` مستند شده.

## دانلود APK از GitHub Actions

1. در ریپازیتوری گیت‌هاب، تب **Actions** را باز کنید.
2. روی آخرین اجرای موفق ورک‌فلو **«Build HamSeda APK»** کلیک کنید.
3. به پایین صفحه بروید، بخش **Artifacts** → فایل **`HamSeda-debug-apk`** را دانلود کنید.
4. فایل ZIP را باز کنید؛ داخل آن `app-debug.apk` و `app-debug.apk.sha256` است.
   قبل از نصب، هش را بررسی کنید:
   ```bash
   sha256sum app-debug.apk  # باید با محتوای app-debug.apk.sha256 یکی باشد
   ```
5. `app-debug.apk` را روی گوشی نصب کنید.

اجرای دستی: تب Actions → «Build HamSeda APK» → دکمه **Run workflow**.

## ساخت نسخه امضاشده (ریلیز)

APK دیباگ با کلید دیباگ امضا شده و برای **تست** مناسب است، نه انتشار عمومی.
برای انتشار:

1. یک keystore خصوصی بسازید و **هرگز** آن را در ریپازیتوری کامیت نکنید.
2. مشخصات امضا را در GitHub Secrets بگذارید (مثلاً `KEYSTORE_BASE64`،
   `KEYSTORE_PASSWORD`، `KEY_ALIAS`، `KEY_PASSWORD`).
3. یک ورک‌فلو جداگانه `release.yml` بسازید که keystore را از سکرت بازسازی
   و `assembleRelease` را امضا کند. نمونه آماده در این ریپو نیست چون بدون
   سکرتِ شما قابل تست نیست — عمداً چیزی جعل نشده است.

## عیب‌یابی بیلد

| مشکل | راه‌حل |
|---|---|
| `SDK location not found` در CI | ورک‌فلو خودش `platforms;android-37` و `build-tools;36.0.0` را نصب می‌کند؛ اگر رانر عوض شد، لاگ مرحله «Set up Android SDK packages» را ببینید |
| خطای نسخه Gradle | فقط از wrapper کامیت‌شده (`./gradlew`) استفاده کنید، نه Gradle سیستمی |
| `NEARBY_WIFI_DEVICES` روی اندروید ۱۲ به پایین | این مجوز فقط در ۱۳+ درخواست می‌شود؛ روی قدیمی‌ترها مجوز موقعیتِ محدودشده با `maxSdkVersion` اعمال می‌شود |
| بیلد محلی بدون Android SDK | `local.properties` بسازید با `sdk.dir=...`؛ یا متغیر `ANDROID_HOME` را ست کنید |
